# P1 database foundation
core.sql is a draft for a clean database, not a generated Supabase migration. CI uses a disposable PostgreSQL 16/PostGIS container and test-only auth stubs; never deploy bootstrap.sql. Validate on a real local Supabase instance, inspect extension schema (public or extensions), run database advisors, generate a migration using Supabase CLI and re-test before hosting. No hosted project has been modified.
All exposed tables have RLS, owner-only reads and no client writes. The backend must validate identity, driver eligibility, capacity against vehicle limits, stop order and booking counts in transactions (P2/P3). Actual public search needs a privacy-safe API. Storage buckets/policies, auth provisioning, expiry cleanup and transactional booking API are not implemented yet. Expired holds remain blocking until status changes, by design.
